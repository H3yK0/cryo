# Receita do F-Droid na 1.6 (rascunho para o lançamento)

A 1.5 saiu só no GitHub (16/11/2026): ela levava o modelo do Whisper dentro do APK (57 MB de pesos prontos), e o F-Droid, que
compila do código-fonte, recusa binários que não saem de código nenhum (ERR-057). Na 1.6 o modelo saiu do app (RF-VOZ-15):
a pessoa baixa pelo navegador e o Cryo confere o SHA-256. Por isso a loja vai da 1.4 direto para a 1.6.

A 1.6 tem código nativo (a ponte do Whisper, RF-VOZ-10). O robô do F-Droid copia o último bloco de `Builds:`, que é o da 1.4 e
não tem NDK: no lançamento é preciso abrir um merge request no fdroiddata com o bloco abaixo (com o commit da etiqueta `v1.6`).
**Atualização de 22/11/2026 (merge request !58632):** a receita oficial já tem a 1.5, posta pelos mantenedores do F-Droid
com o modelo liberado no scanner (`scanignore`) e `CurrentVersion: '1.5'`. Então o bloco da 1.5 **fica como está** (nada de
`disable:`), e o merge request só acrescenta a 1.6 e troca o fim do arquivo. A primeira versão deste rascunho reprovou em
três jobs do CI (`schema validation`, `fdroid rewritemeta` e `fdroid build`): faltava `AutoUpdateMode` (obrigatório),
`disable:` vinha depois de `commit:` e numa linha longa demais, `sudo:` com um comando só era lista e faltava a quebra de
linha no fim. **Toda receita passa antes pelas mesmas conferências do CI** (`check-jsonschema` com o `schemas/metadata.json`
do fdroiddata e `fdroid rewritemeta` sem diferença; ver `docs/ERROS.md`, regras sem guarda automática).

O bloco da 1.6 (no formato que o `fdroid rewritemeta` aceita):

```yaml
  - versionName: '1.6'
    versionCode: 11
    commit: ddeb228ec0b7de1a830177271632a8744cf0046e
    subdir: app
    sudo: sdkmanager "cmake;3.22.1"
    gradle:
      - yes
    ndk: r27c
```

E o fim do arquivo, com a linha `AutoUpdateMode` mantida e uma quebra de linha no final:

```yaml
AutoUpdateMode: Version
UpdateCheckMode: Tags ^v[0-9.]+$
CurrentVersion: '1.6'
CurrentVersionCode: 11
```

E trocar `UpdateCheckMode: Tags` por `UpdateCheckMode: Tags ^v[0-9.]+$`: o repositório passa a ter também a etiqueta
`voice-model-1` (uma Release que só guarda o arquivo do modelo, `docs/VOZ-MODELOS.md`), e o robô não pode tomá-la por uma
versão. A Release `voice-model-1` é criada com **Target = branch `versao-1.4`**, para a etiqueta ficar num código antigo.

Por que cada linha:
- `ndk: r27c` = o `ndkVersion = "27.2.12479018"` do `app/build.gradle.kts`. Outro NDK daria outro binário e o APK do F-Droid
  não bateria com o da Release.
- `cmake;3.22.1` = a versão fixa do `externalNativeBuild` (o Gradle procura exatamente essa).
- Nenhum binário pronto no repositório (`SourceTreeTest`); o modelo não está mais em `app/src/main/assets/`.

Texto para o merge request (em inglês):
- *Cryo 1.6. The Whisper model is no longer bundled: users download it once with their browser and the app checks its
  SHA-256 (the app still has no INTERNET permission). Native code (whisper.cpp, MIT) is built from source with NDK r27c.*
- *`UpdateCheckMode` now only looks at `v*` tags: the repository also has a `voice-model-1` tag, a release that only holds
  the model file.*
